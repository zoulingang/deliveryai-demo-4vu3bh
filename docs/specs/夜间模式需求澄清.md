# 夜间模式 需求澄清文档

> 文档版本：v1.0  
> 所属仓库：`zoulingang/deliveryai-demo-4vu3bh`（沸点火锅点单演示）  
> 目标分支：`feat/dark-mode-jbm8`（基于 `main`）  
> 创建时间：2026-09-13

---

## 1. 一句话概述

在沸点火锅点单演示产品中新增夜间模式能力，提供浅色/深色/跟随系统三种主题切换，使用户在暗光环境下也能舒适地完成桌台绑定、点餐、订单查看、呼叫服务等全流程操作，同时保持现有老人模式、中英文切换、点餐履约等功能不受影响。

---

## 2. 背景与目标

### 背景
- 当前产品仅提供浅色主题（米白底 + 辣椒红 + 炭黑），在夜间或暗光环境（如夜晚就餐场景、灯光昏暗的包间）下用户长时间使用时屏幕亮度对比过大，易产生视觉疲劳。
- 产品已具备老人模式（字号放大、对比度增强）和中英文切换能力，主题系统是用户可访问性与个性化体验的重要补充。
- 本次作为概念演示项目的体验完善，对齐现代 Web 应用的标准夜间模式能力。

### 目标
- 提供浅色、深色、自动（跟随系统）三种主题选项，用户可随时切换。
- 深色主题采用暖色调深色方案（深炭/暖黑底 + 保留辣椒红/琥珀品牌色），保持品牌视觉一致性，同时保证暗光环境下的舒适度。
- 所有页面与组件（桌台绑定、欢迎页、点餐、购物车、订单、结账、服务呼叫、会员弹窗、演示控制台）在深色模式下均显示正常，无对比度不足、颜色错乱、内容不可读问题。
- 深色模式满足 WCAG 2.1 AA 对比度标准（普通文本 ≥4.5:1，大文本 ≥3:1）。
- 主题偏好持久化到本地（localStorage），刷新页面、重新打开后保持用户选择；预留跨设备同步接口位，待真实账号体系接入后对接。
- 与现有老人模式互相独立、可叠加使用：深色模式提供基础对比度保障，老人模式在任意主题下额外放大字号并进一步增强半透明文字不透明度。
- 主题切换使用平滑过渡动画（与现有老人模式一致，250ms ease），不出现闪烁或突兀跳变。

### 不做（本次范围外）
- **不新建独立"设置页面"**：主题切换入口采用顶部栏图标按钮 + 弹出分段控件，与现有老人模式、语言切换交互范式保持一致，不重构现有导航结构。
- **不实现真实跨设备云同步**：主题偏好仅本地持久化；代码中可预留 sync hook 接口位置并加 TODO 注释，但不扩展 server 端接口，不引入账号/登录体系。
- **不调整品牌主色（chili 红、amber 黄）的色相**：深色模式下仅调整背景、文字、边框、卡片底色，品牌强调色沿用现有色系并保证可读性。
- **不修改点餐、购物车、订单、结账、服务呼叫等业务逻辑**：仅涉及视觉呈现层。
- **不新增除主题切换外的其他个性化选项**（如自定义主色、字体等）。

## 3. 需求详情

### 用户场景

| 场景 | 用户与上下文 | 期望结果 |
|------|-------------|---------|
| S1 首次夜间访问 | 新用户在系统为深色模式时首次打开应用（或扫桌码） | 自动呈现深色主题，无需手动操作即可舒适阅读 |
| S2 手动切换 | 用户在点餐过程中觉得屏幕过亮/过暗，想快速切换主题 | 在顶部栏点击月亮图标，从浅色/深色/自动中选择，切换即时生效 |
| S3 选择自动模式 | 用户希望应用随系统昼夜自动切换 | 选择"自动"后，系统深浅色变化时应用跟随切换，无需再次手动操作 |
| S4 刷新/重开 | 用户切换主题后刷新页面或关闭后重新进入 | 主题偏好保持上次选择，不会重置为默认 |
| S5 叠加老人模式 | 视力不佳用户在深色下开启老人模式 | 字号放大 1.25 倍，半透明文字对比度进一步增强，两种效果叠加不冲突 |
| S6 全流程浏览 | 用户从绑桌 → 欢迎 → 点餐 → 下单 → 查看订单 → 结账，全程深色 | 每个页面的卡片、弹窗、按钮、徽标、提示、空态、加载态均配色合理，无内容看不清 |

### 用户路径（主流程：手动切换主题）

1. 用户在任意已绑定桌台的页面（菜单页/订单页等）浏览内容。
2. 用户点击顶部栏右侧的主题切换图标按钮（月亮/太阳图标，与老人模式、语言按钮同排）。
3. 弹出轻量级分段选择控件（或 Popover/下拉面板），展示三个选项：**浅色**、**深色**、**自动（跟随系统）**，当前选中项高亮。
4. 用户点击任一项，主题立即切换（带 250ms 平滑过渡动画），面板自动关闭。
5. 选择结果保存到 localStorage；后续刷新、重开页面均保持该选择。
6. 用户继续在新主题下完成点餐等操作，所有页面视觉正常。

### 用户路径（异常路径：localStorage 不可用）

1. 用户在隐私模式/禁用 localStorage 的浏览器中操作。
2. localStorage 读写抛错时，降级为内存态：当前会话内主题切换仍生效，但关闭页面后不持久化，下次打开恢复默认（自动模式）。
3. 不阻塞页面渲染，不弹报错提示。

### 产品规则

#### 主题状态与优先级
- **R1**：主题状态为三值枚举：`light`（浅色）、`dark`（深色）、`auto`（自动跟随系统）。
- **R2**：初始加载优先级：localStorage 中已保存的偏好 > 默认值 `auto`。
- **R3**：当主题为 `auto` 时，实际呈现效果跟随 `window.matchMedia('(prefers-color-scheme: dark)')` 的当前值；系统主题变更时页面实时响应切换。
- **R4**：当用户手动选择 `light` 或 `dark` 后，覆盖系统偏好，不再跟随系统变化，直到用户重新选择 `auto`。
- **R5**：主题切换即时生效，无需刷新页面，无需二次确认。

#### 主题应用方式
- **R6**：在 `<html>` 根元素上通过 class 标记主题状态：
  - 浅色：`class="light"` 或无 dark class（兼容现有样式）
  - 深色：`class="dark"`
  - 自动模式下不额外加 class，通过 `@media (prefers-color-scheme: dark)` 响应，或 JS 动态添加 `dark` class（推荐后者，便于 Tailwind `darkMode: 'class'` 管理）。
- **R7**：主题状态通过 React Hook（参考 `useElderlyMode.ts` 范式实现 `useTheme`）统一管理。
- **R8**：主题切换过程中保持现有过渡动画：背景色、文字色、边框色、填充色 250ms ease 平滑过渡，避免闪烁。

#### 深色模式配色规则（暖色调深色方案）
- **R9**：页面底色：使用深炭色/暖黑色系（基于现有 charcoal 色阶扩展 dark 变体，如 `charcoal.950`、`charcoal.900`），避免纯黑 `#000` 造成刺眼。
- **R10**：卡片/弹层底色：略浅于页面底色（如 `charcoal.900`/`charcoal.800`），配合低透明度描边而非纯阴影建立层级。
- **R11**：主文字：高亮度暖白（如 `rice.50`/`rice.100`）；次要文字/说明文字：降低不透明度但保证 AA 对比度。
- **R12**：品牌强调色（chili 红、amber 黄）保留色相，必要时微调亮度/饱和度以保证深色背景下对比度与辨识度。
- **R13**：辣椒红主按钮在深色下保持视觉识别，可适当提亮 `chili.500` → `chili.400` 或保持 `chili.500` 但增加外发光/描边辅助识别。
- **R14**：米纸噪点纹理（`.paper-noise`）需要在深色下调整为深色版纹理或降低不透明度，不可在深色背景上出现浅色噪点。
- **R15**：图片、菜品图、图标（lucide-react）保持原色显示，但图标颜色需通过 `currentColor` 或显式深色样式适配。
- **R16**：半透明/玻璃拟态元素（如 `backdrop-blur-xl` 顶栏、会员弹窗渐变头图）需调整背景色与透明度，保证深色下可读且层级清晰。

#### 无障碍规则
- **R17**：所有普通正文文本与其背景的对比度 ≥ 4.5:1（WCAG 2.1 AA）。
- **R18**：所有大文本（≥18pt 常规字重 / ≥14pt 粗体）与背景的对比度 ≥ 3:1（WCAG 2.1 AA）。
- **R19**：焦点态（focus ring）在深色背景下需可见，不可与背景融为一体。
- **R20**：主题切换按钮需具备 `aria-label`（中文"切换主题"、英文"Toggle theme"），当前选中状态需通过 `aria-pressed` 或视觉高亮表达。
- **R21**：主题图标需提供 `prefers-reduced-motion` 降级：用户开启减少动画偏好时，关闭主题切换过渡动画。

#### 与老人模式叠加规则
- **R22**：老人模式和夜间模式互相独立，状态不互斥，可以同时开启。
- **R23**：老人模式开启时，无论当前是浅色还是深色主题，字号均放大为 125%（现有行为保持）。
- **R24**：老人模式下的半透明文字增强规则（`.text-rice-200\/40`、`.text-white\/*` 等）在深色主题下需同步适配深色专用半透明文字（如深底上的浅色半透明文字），确保对比度达标。
- **R25**：老人模式在深色下不二次叠加全局对比度滤镜，避免颜色失真；仅针对具体半透明工具类做不透明度提升。

#### 与中英文切换叠加规则
- **R26**：主题切换与语言切换完全正交，语言切换时保持当前主题不变，主题切换时保持当前语言不变。

#### 持久化与同步预留
- **R27**：主题偏好存储 key 建议为 `theme`（或 `theme-mode`），值为 `light`/`dark`/`auto` 字符串。
- **R28**：localStorage 读写失败时（隐私模式、配额超限等）静默降级为内存态，不抛错、不弹提示、不阻塞主流程。
- **R29**：代码中预留主题偏好同步接口位（可在 `useTheme` hook 中暴露 `syncThemePreference` 占位函数或注释标记 `// TODO: 接入账号体系后调用服务端同步接口`），但本次不实际发起网络请求。

### 状态与反馈

| 状态 | 用户可感知结果 |
|------|--------------|
| **成功（切换）** | 选择某主题后，面板关闭，整站主题在 250ms 内平滑过渡到新主题；图标按钮根据当前主题切换视觉（如浅色显示月亮、深色显示太阳、自动显示日月叠加图标，具体以设计实现为准）。不弹出 toast 提示（避免打扰），与现有老人模式带 toast 的行为**区分**：主题切换为即时可见的视觉反馈，不需要额外文字提示。 |
| **失败** | 主题切换为纯前端操作，无网络请求，正常不失败；localStorage 写入失败时静默降级，用户无感知。 |
| **空态/首次访问** | localStorage 无记录时默认 `auto`，跟随系统；若浏览器不支持 `prefers-color-scheme`（极旧浏览器），降级为浅色主题。 |
| **无权限** | 主题切换无权限控制，所有访问者（包括未绑定桌台的绑桌页、欢迎页用户）均可使用。 |
| **异常（系统主题变化）** | 用户处于 `auto` 模式时，系统从浅色切到深色或反之，页面应平滑跟随切换；若用户已手动选择 `light`/`dark`，系统变化不影响当前主题。 |
| **保持不变** | ①点餐业务流程（加购、改量、下单、取消、结账、服务呼叫）行为完全不变；②中英文切换功能与文案完全不变；③老人模式放大字号与触控区域增强规则完全不变；④预览模式（`?preview=menu`）入口与行为不变；⑤现有页面路由/视图切换逻辑不变。 |

### 关键表现要求

- **视觉风格**：深色模式延续暖色品牌质感，避免冷蓝黑造成品牌割裂感；背景不使用纯黑 `#000`，使用深炭暖灰。
- **层级表达**：深色下减少大阴影投射（阴影在深底上不明显），改用描边 + 背景色阶差来表达卡片层级。
- **过渡动画**：全局颜色相关属性（background-color、border-color、color、fill、stroke）250ms ease 过渡，复用现有 `html *` 过渡规则，注意排除 transform/opacity 等不必要属性以免影响性能。
- **切换入口**：顶部栏图标按钮与老人模式（Accessibility 图标）、语言切换按钮视觉权重一致，使用 `variant="outline" size="icon"` 的 Button 样式。
- **弹出面板**：使用 Radix UI 或现有 Dialog/DropdownMenu 类组件实现三选一控件，点击选项后立即生效并关闭面板，点击面板外区域也可关闭。
- **减少动效**：尊重 `prefers-reduced-motion: reduce`，关闭颜色过渡动画。

## 4. 约束限制

- **技术栈约束**：使用现有 React 18 + TypeScript + Tailwind CSS + Radix UI + lucide-react 技术栈实现；不引入新的 UI 库或主题库（如 next-themes、mui 等），参考 `useElderlyMode.ts` 自研轻量 hook。
- **Tailwind darkMode 策略**：建议启用 `darkMode: 'class'`（在 `tailwind.config.js` 中配置），通过 `<html>` 根元素 class 控制深色样式；自动模式下 JS 监听 `prefers-color-scheme` 变化并动态增删 `dark` class。
- **兼容要求**：
  - 现代浏览器（Chrome/Edge/Firefox/Safari 最近两个大版本）深色模式完整可用；
  - 不支持 `prefers-color-scheme` 的旧浏览器降级为浅色；
  - 禁用 localStorage 的浏览器降级为内存态；
  - 现有 e2e Playwright 用例在浅色主题下应保持通过，不得因主题改动破坏原有断言（必要时在测试中显式设置浅色主题）。
- **性能要求**：
  - 主题切换不得引起明显卡顿；
  - 不得在每次渲染时重复读取 localStorage；
  - CSS 体积增量控制在合理范围内（建议复用 Tailwind dark: 前缀，避免大量重复自定义 CSS）。
- **稳定性要求**：
  - 主题初始化逻辑在首屏渲染前或早期同步执行，避免 FOUC（闪烁）问题；建议在 `index.html` 中放置内联 script 尽早读取 localStorage 并设置 `dark` class，或在 `main.tsx`/`App.tsx` 最早期同步应用。
  - 任何情况下主题相关异常不得阻塞页面主功能渲染。
- **代码规范**：遵循现有 ESLint 配置（`npm run lint` 必须通过）；TypeScript 类型完整无 `any`。
- **实现边界**：
  - 不重构现有颜色引用为 CSS 变量，优先用 Tailwind `dark:` 前缀；
  - 少量需要复用的自定义深色样式放入 `src/index.css`，参考现有 `.elderly` 规则写法；
  - 不改动 server 端代码。
- **i18n**：新增文案必须中英双语同步维护。

---

## 5. 验收标准

- **[主流程-手动切换]** 用户已绑定桌台进入菜单页，点击顶部栏主题按钮，弹出包含"浅色/深色/自动"三个选项的控件；点击"深色"后，全站（顶栏、菜单、购物车、订单、底部操作栏）在 250ms 内平滑切换到深色主题，面板自动关闭。
- **[主流程-自动模式]** 用户选择"自动"后，切换操作系统深色/浅色设置，浏览器页面应在 500ms 内跟随切换为对应主题。
- **[主流程-浅色切换]** 在深色主题下点击"浅色"，页面恢复为现有浅色米白配色，视觉表现与改动前一致。
- **[持久化]** 用户选择深色后刷新页面、关闭标签页重新打开，页面加载后直接呈现深色主题，不出现先浅后深的闪烁。
- **[全页面覆盖]** 逐一检查以下页面/组件在深色模式下文字可读、按钮可辨识、图片/图标显示正常、无对比度 < 4.5:1 的正文文本：①BindTable 绑桌页；②WelcomeView 欢迎页；③MenuView 菜单页（含菜品卡、售罄徽标、搜索框、分类 tab、辣度弹窗）；④CartPanel 购物车；⑤CheckoutView 结账页；⑥OrderView 订单页（含各阶段状态）；⑦ServiceSheet 服务呼叫面板；⑧会员 Dialog（含渐变头图、排号/权益卡）；⑨DemoConsole 演示控制台；⑩TopBar 顶栏；⑪风险提示 Dialog（超级辣提醒）。
- **[无障碍对比度]** 使用浏览器 DevTools/对比度检查工具抽查主要文本（标题、正文、按钮文字、次级说明文字、链接、置灰文字），普通文本对比度 ≥ 4.5:1，大文本 ≥ 3:1，无对比度警告。
- **[老人模式叠加]** 在深色模式下开启老人模式，字号放大 1.25 倍，所有文字保持可读；老人模式下按钮最小高度 ≥ 2.2rem 保持生效；关闭老人模式后字号恢复。
- **[语言切换正交]** 在深色下切换中英文，主题保持深色且文案正确切换；再切回中文，主题仍为深色。
- **[入口视觉与 a11y]** 顶部栏主题按钮有可识别的图标（月亮/太阳/自动标识），具备 `aria-label`；弹出控件中当前选项有明确高亮状态。
- **[过渡动画]** 主题切换时背景色、文字色、边框色平滑过渡（250ms ease），无突兀跳变；开启系统"减少动画"偏好时，无过渡动画直接切换。

# 概念演示产品边界

## 预期行为

用户可以在浏览器中独立体验桌台绑定、菜单浏览、多人点餐、出餐进度、服务呼叫和模拟结账；产品始终明确展示为概念演示，不要求真实账户、支付或后端服务即可完成体验。

## 验收条件

每条用 `### <AC-ID> <描述>`，必须能独立判定通过与否。
Evidence 用 `REQ-DEMO-001#AC-01` 这样的形式引用它们。

### AC-01 核心点餐流程可体验

启动前端后，用户能够从桌台绑定进入菜单，添加商品并继续体验出餐、服务呼叫和模拟结账流程。

### AC-02 不依赖生产系统

核心体验不要求用户登录，不发起真实支付，也不依赖真实订单、账户或汇率服务。

### AC-03 概念演示身份可见

界面保留“概念演示 / 非官方”含义的可见说明，不能让用户误认为它是生产点餐系统。

## 非目标

- 不提供真实账户、鉴权或用户数据管理。
- 不处理真实订单、支付、退款或结算。
- 不接入实时汇率、餐厅后台或其他生产外部 API。

## 约束

- 部署目标是 GitHub Pages，必须保持对相对基础路径的兼容。
- 所有用户可见文本同时提供中文和英文版本。
- 主题、币种和老年模式等偏好在本地不可用时必须安全降级，不能阻断核心流程。
